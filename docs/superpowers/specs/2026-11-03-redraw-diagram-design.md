# 以資料重繪線路圖（取代原廠掃描底圖）設計

日期：2026-11-03

## 目的與原因

- 這個網站之後要公開。原廠 PDF 已經排除在 git 之外，但 `data/<圖>/strips.js` 是原廠掃描圖的像素，仍等於照搬原檔。
- 改成用自己的資料、以**簡化示意風格**重新畫圖，畫法和原圖明顯不同，只保留版面位置（哪個元件在哪、線怎麼走）。
- 使用者的優先順序是「能解決修車問題」。這次只做重繪，讓現有功能在新圖上照常運作；修車導向的新功能（腳位、量測點等）之後另案處理。
- 之後要能在新圖上畫改裝圖（例：發電機改三相、加三相整流穩壓器），所以資料必須是「人和 Claude 都容易增刪改」的形式。

## 目標

1. PA12B、PA12C 兩張圖都改由資料繪製，最後**直接移除** `strips.js`，網頁不再載入任何原廠影像。
2. 新圖的接線關係和現在一致（見「驗收」）。
3. 現有功能照常運作：點線／點元件亮線、Shift 多選、塗色、儲存與匯入匯出選取、開關導通表、線色對照點選、隱藏接地線、淡化底圖、兩張圖切換。（「圈選細節」淘汰，見下。）
4. 資料格式方便日後新增元件、導線、接頭（改裝圖）。

## 非目標

- 腳位編號、量測點與參考值、依症狀查線等修車功能。
- 三相改裝圖本身（只要求格式能支援）。
- 版面重新排版或美化；位置沿用原圖座標。
- 照原圖逐筆描繪符號（那是被否決的 B 方案）。
- 補齊未標線色的導線顏色（使用者決定：先畫成灰色，之後另案補）。
- 「圈選細節」功能（使用者決定淘汰：它是用來回報辨識錯誤的，新圖不再有辨識）。

## 反目標（做到了也算失敗）

- 新圖少了導線、接錯線，或線色和原圖不同。修車時照圖查錯線比沒有圖更糟。
- 既有的匯出檔（`wolf125-selections.json`、`wolf125-<圖>-selections.json`）和瀏覽器裡已存的選取、塗色在新圖上失效，或塗色塗到別條線上。（匯出檔中的「細節」項目例外：隨功能淘汰，匯入時略過並提示。）
- 新圖中仍殘留原廠影像像素（例如把原圖裁一塊貼上當符號）。

## 限制

- 靜態網站，無建置步驟；資料檔是 `window.WOLF_* = …` 形式的 `.js`，由 `js/diagrams.js` 的 `DATA_FILES` 動態載入。
- **座標系統不變**：全解析度 3323×2188，原點左上。已存選取以「線上一點的座標（pick）」記錄，`components.js` 的 `picks`、`switches.js` 的 `pins` 也是座標；新圖的導線必須經過這些點附近（現有 hit 半徑內），它們才找得回對應的線路。
- `components.js` 的 `box`、`label` 以圖寬 1800 為基準（乘 3323/1800），沿用不改。
- 不得引入原廠影像；字型使用系統字型（現有頁面已用的字型堆疊）。

## 已決定的做法

### 資料：新增 `data/<圖>/drawing.js`

以「線路網」為單位，連線關係**明確寫在資料裡**，不再從影像辨識。結構（欄位名稱可由實作者微調，但語意不變）：

```js
window.WOLF_DRAWING = {
  size: [3323, 2188],
  nets: [
    // 一條線路網：線色、是否接地、組成它的折線、接點圓點
    { code: 'G/R', ground: false,
      wires: [[[1030, 826], [1042, 826], [1042, 837], [1200, 837]], …], // 每條是水平／垂直折線
      dots: [[1042, 837]] },
    { code: 'B', cable: true, half: 9, ground: true, wires: [...] },   // 粗電纜（原 fixes.cables）
  ],
  connectors: [ { label: '9P', box: [x0, y0, x1, y1] }, … ],          // 線上接頭方框
  inline: [ { kind: 'plug', at: [x, y], dir: 'h' }, … ],               // 三角形＋方框的單線接頭
  labels: [ { text: 'G/R', at: [x, y], vertical: false }, … ],         // 線色文字
  texts:  [ { text: '野狼傳奇 125', at: [x, y], size: 28 }, … ],       // 標題等
};
```

- **同一張圖內，線路網在陣列中的順序就是線路編號**；元件、選取都靠座標反查，不依賴編號。
- 元件仍放在 `components.js`，新增 `symbol` 欄位：`'block'`（預設：方框＋名稱）、`'lamp'`、`'ground'`、`'diode'`、`'fuse'`、`'battery'`、`'coil'`、`'switch'` 等少數標準符號；沒有 `symbol` 就畫方框。符號是**通用電路符號**，不是照原圖描。
- 未標線色的線路網 `code: null`，畫成深灰色（使用者決定；之後另案人工補線色時只需填 `code`）。

### 初始資料的產生（一次性）

- 寫一支 Node 腳本（放在 skill 或 `tools/`），用現有辨識結果（`js/nets.js` ＋ `anchors`／`fixes`）把每條線路網的導線線段轉成折線，輸出 `drawing.js` 的草稿：合併共線線段、座標取整到線段中心線、偵測到的接點寫成 `dots`、`cables` 轉成 `cable: true` 的線路網。
- 非導線筆畫（元件符號、文字、表格）不轉；改由 `components.js` 的 `symbol`、`connectors`、`labels` 重新表示。
- `staticAreas` 範圍（底部開關表、線色表）整塊不畫；這兩個表側欄已有 HTML 版。
- 草稿產生後由人工（Claude）逐區比對原圖補齊：接頭方框、線色文字、元件符號種類、辨識漏掉或誤併的地方。

### 網頁：照資料繪製，保留像素式的互動層

為了讓現有功能幾乎不必改，**保留 `label`（每像素屬於哪條線路）這個核心結構**，只換掉它的來源：

1. 載入 `drawing.js`，在畫布上依資料畫出底圖（導線、圓點、元件符號、接頭、文字），取代現在的 `strips.js` 拼接。
2. `label` 改成**把每條線路網的折線點陣化**（線寬與現在相近）寫入，而不是跑 `analyzeNets`。
3. `nets[k]` 的 `code`、`ground` 直接取自資料；`buildGround` 的「平均顏色偏綠」推測改成讀 `ground` 欄位（元件 `ground: true` 的連帶規則保留）。
4. 依賴原圖像素的地方改用新圖：`compLayer`（選取元件時以原亮度疊上符號）改為重畫該元件符號；`STATIC_AREAS` 與 `analyzeNets`、`strips.js` 載入在最後一步移除。
5. 其餘（`stamp`、`hitTest`、選取、儲存、開關表、線色對照）沿用。
6. **塗色改用座標儲存**（Claude 的決定）：現在 `paint` 以線路編號為 key、只檢查總數，新圖編號順序必然改變，照舊會把顏色塗到別條線。改成和已存選取一樣記錄「線上一點的座標」；並寫一次轉移：在舊辨識結果上把 `paint[k]` 轉成座標，存成新格式（新的 localStorage key），舊 key 保留不刪。
7. **淘汰「圈選細節」**：移除畫框模式、相關按鈕與 `details` 的儲存；匯入含細節的 JSON 時略過那些項目，訊息告知略過幾筆。

### 驗收

1. **接線一致**：以現有辨識結果為基準，對每條舊線路網取線段中點，查它在新 `label` 中的線路；舊→新必須是一對一（不可一分為二，也不可兩條併成一條）。
   - 整批例外（Claude 的決定）：完全落在元件 `box`／`label` 範圍內的舊線路網，視為元件符號或文字的筆畫，新圖不畫，只列出數量。
   - 其他例外須逐條列出原因（例如原本就是辨識錯誤、這次順便修正），並經使用者確認。
2. **既有參照全部找得回**：`wolf125-selections.json` 每個單元仍落在 1 條線路；每個元件的 `picks`、每個開關的 `pins` 都落在有線路的位置；轉移後的塗色，每一筆都落在和舊圖同一條（依驗收 1 的對應）線路上。
3. **線色一致**：每條線路網的 `code` 與現在的辨識結果相同（`null` 維持 `null`）。
4. **目視**：每張圖分區（約 6～8 區）與原圖並排截圖比對，確認沒有漏線、元件位置與名稱正確。
5. **Chrome 實測**：沿用 `acceptance.js` 的做法，在 headless Chrome 開真正的頁面跑上述檢查。
6. 完成後專案內不再有原廠影像：`strips.js` 刪除，`git grep 'data:image'` 無結果。

### 分階段（每階段結束都可用、可驗收）

1. **資料化＋導線**：產生 `drawing.js` 草稿；網頁改由資料畫導線、圓點、元件方框與名稱；`label` 改由資料產生；驗收 1～3 通過。此時保留一個暫時開關可疊回原圖對照（僅開發用，最後移除）。
2. **接頭與線色文字**：補 `connectors`、`inline`、`labels`。
3. **元件符號**：為常見元件加 `symbol`，畫通用符號。
4. **移除原圖**：刪 `strips.js`、`staticAreas`、`analyzeNets` 的執行期使用與暫時對照開關；驗收 4～6。
5. **工具與文件**：改寫或淘汰 `fixing-wire-nets`、`editing-diagram-image` 兩個 skill（它們針對掃描圖辨識與改圖），改成「編輯 `drawing.js`」的流程；更新 `js/diagrams.js` 的檔案清單說明。

PA12C 與 PA12B 共用程式；PA12C 的資料在 PA12B 完成後以同一支腳本產生、再補油量指示燈等差異。

## 留給實作者決定

- 符號的具體畫法、線寬、字級、配色細節（以清楚、印出來可讀為原則；導線顏色沿用 `app.js` 的 `WIRE`）。
- 用 Canvas 2D 直接畫或先組 SVG 再畫入畫布。
- 草稿產生腳本的合併規則、座標取整方式。
- `drawing.js` 欄位的細部命名與是否拆成多個檔案。
- 舊的 `js/nets.js` 是否保留作為產生草稿的工具（執行期不再使用）。
